# Waveform viewer (VaporView)

The waveform viewer that cmux opens for `.vcd`, `.fst`, `.ghw` and `.fsdb`
files is VaporView's webview, built from source and hosted in a WKWebView
without VS Code.

- Upstream: https://github.com/Lramseyer/vaporview
- Commit: `59107c60c9ee5eefa95750b95369753736b77ca4` (tag `1.6.1-beta`)
- License: GNU General Public License v3.0 (`LICENSE`, copied from upstream)
- Author: Lloyd Ramseyer (GitHub `Lramseyer`) and the VaporView contributors

## How these files were built

From a clean checkout of the commit above, with Rust (`wasm32-unknown-unknown`),
`wasm-tools` and Node.js:

```sh
git apply <cmux>/Resources/vaporview/source/cmux-vaporview.patch
npm ci
npm run compile-wasm          # wit2ts bindings + cargo build --release for wasm32
node esbuild.js --production  # minified dist/webview.js
```

`source/cmux-vaporview.patch` is cmux's change to VaporView's sources (the
GPL's corresponding source for `webview.js`), made on branch `simctl` (off
`cmux-viewer`) at `eea3c553c71dbef1368baa93802096fdd7bc4131`. It leaves out only the
gzipped objdump outputs the RISC-V tests compare against (`test/riscv/*.gz`,
regenerated by `test/riscv/make_expected.sh`). The build above reproduces the
bundled `webview.js` byte for byte.

The bundled npm and Rust dependencies, with their licenses, are listed under
"Waveform Viewer Assets" in the repository's `THIRD_PARTY_LICENSES.md`.

## Local modifications

Made by cmux on 2026-10-30 (viewer, host, FSDB helper; then escaping,
Content-Security-Policy and FSDB helper hardening; then VaporView's menus,
keybindings, netlist view, settings, sessions and terminal links).

- `webview.js`, through `source/cmux-vaporview.patch` (each change is
  described in the patch's `CHANGES.md` and in comments marked `cmux:`):
  - Escaping. Waveform data reaches `innerHTML` unescaped in upstream
    `src/webview/` (an upstream bug, to be reported): the
    `data-vscode-context` attribute is written unquoted (`signal_item.ts`),
    label tooltips escape `<>` but not `"`, the drag tag sets `innerHTML` to
    the dragged signal's name (`labels.ts`), and value text from the file is
    not escaped. The patch quotes and escapes each once, where the HTML is
    built; `scripts/waveform-viewer-checks/run.sh xss` checks it.
  - `handleRemoveVariable` (`row_handler.ts`) skips a row already queued: with
    an expanded group, `applyState` passes the group and its children, and the
    second `dispose()` threw (Undo, Redo, session loads; an upstream bug, to be
    reported). `run.sh parity` (phase O) checks it.
  - Exact value search (`value_search.ts`). Upstream's numeric
    `checkSearchValue` (`regexMatchBinary` in `value_format.ts`) tests the search
    as an unanchored regex over the value's bits, so hex 5 also matched 0x15. The
    patch anchors that same regex to the whole value (with zero or sign
    extension), as Verdi searches. Wildcards and regexes still work, so
    `.*0101.*` is still a substring search. The signed format's search keeps its
    sign bit, so +5 is not -3. VaporView's `test/riscv/search.test.ts` checks it.
  - Value formats: a RISC-V instruction format (`riscv_disasm.ts`,
    `extra_formats.ts`) and Verdi-style value alias files (`value_alias.ts`).
  - Windowed loading (`window_cache.ts`, written for cmux) for an FSDB opened
    through the v2 helper: a signal's data is a set of windows the viewer asks
    the helper for (`{command: 'v2'}` / `v2-reply` messages, enabled by
    `set-windowing`), with small signals loaded whole, prefetch, and marker
    values, next/previous edge, value search and WaveDrom answered by the
    helper. Value searches in RISC-V, ASCII and alias formats ask the helper's
    `searchText` (formatted and matched next to the dump), else scan exact
    chunks in the viewer. Without `set-windowing` the viewer behaves as upstream.
- `filehandler.wasm`: wellen 0.25.7 (BSD 3-Clause, Kevin Laeufer; https://github.com/ekiwi/wellen)
  merges a VCD's split bits (`valid [0]`, `valid [1]`, as Questa and other writers bit-blast vectors)
  into one vector in `transform_bv_signal` (`src/signal/transform.rs`), which had four mistakes
  (upstream bugs, to be reported):
  - it started each bit at the time-table index instead of the position, so with no bit at the first
    time each bit started at a wrong (usually its second) value;
  - a bit whose first change came after the others' never advanced, so its values were lost;
  - the X of a bit without a value yet was dropped (written as 0) when the bits were 2-state;
  - a bit that is declared but never written emptied the whole vector (its "first time" counted as 0).
  `wellen-0.25.7-split-bit-start.patch` fixes all four. To rebuild, run
  `scripts/waveform-viewer-checks/wellen/build-wasm.sh <VaporView checkout> <work dir>` (Rust 1.93.1 with
  wasm32-unknown-unknown). It vendors every crate, patches wellen in the vendored copy (so it keeps its
  crates.io identity) and remaps the work dir and CARGO_HOME, so the output is the same byte for byte from
  any directory: SHA-1 5375b64ce3ef089af7bd3a85554824343ba28467. With `--unpatched` the same recipe gives
  811a1762fb2d (the old, unremapped plain `cargo build` gave a324478279a2). `wellen/check.sh` runs the
  merge cases on the crate itself (red unpatched, green patched), and `run.sh machine array2late
  array2single` reads them back through the page.
- `index.html`, `viewer.html`: a Content-Security-Policy `<meta>` tag (the
  scheme handler also sends it as a header): only bundled scripts, styles,
  fonts and the wasm, no inline script, no other origin.

- `viewer.html`: the `${webAssets.*}` template placeholders are replaced with
  relative paths, the unused `icons.svg` link is removed, `vscode-theme.css`
  and `vscode-api-shim.js` are loaded in `<head>`, a header comment is added,
  and line endings are LF.
- `vscode-api-shim.js` (new, adapted from `src/webview/vscode_wrapper.ts`):
  provides `acquireVsCodeApi()` and forwards the webview's messages to the
  host page instead of VS Code.
- `wellen-worker.js` (new, adapted from `src/extension_core/worker.ts` and
  `src/extension_core/wasm_handler.ts`): runs `filehandler.wasm` in a Web
  Worker with hand-written canonical-ABI glue in place of
  `@vscode/wasm-component-model`, and reads the file through synchronous
  `Range` requests instead of Node's `fs`.
- `host.js` and `index.html` (new, adapted from
  `src/extension_core/document.ts` and `src/extension_core/viewer_provider.ts`):
  the extension-host side reduced to opening one file, answering the webview's
  `ready` / `initialized` / `fetchDataFromFile` / `copyToClipboard` messages,
  recording `contextUpdate` and `executeCommand setContext` state, and
  answering the netlist search, `getValuesAtTime` and drop requests. The
  wellen worker gains a `getvaluesattime` request.
- `cmux-commands.js` (new, adapted from `package.json` `contributes`,
  `src/extension_core/commands.ts`, `viewer_provider.ts`, `document.ts` and
  the status bar items in `src/extension_core/`): VaporView's context menus
  and submenus (the `webview/context` and `view/item/context` entries with
  their `when` clauses, evaluated against the webview's
  `data-vscode-context`), its keybindings, the `vaporview.*` settings (minus
  the FSDB path, WCP and `fstMaxStaticLoadSize` keys, which do not apply),
  session save/load in VaporView's JSON format, undo/redo, the status strip
  (marker time, delta, selected signal) and the command implementations the
  extension host runs.
- `cmux-netlist.js` (new, adapted from `src/extension_core/tree_view.ts` and
  the netlist search quick pick): the netlist panel, a lazy tree with
  multi-select, add/remove/reveal, drag into the viewer and search.
- `cmux-ui.js` (new): the menu, dialog, quick pick and toast widgets VS Code
  draws natively.
- Where cmux's port behaves differently from VaporView in VS Code:
  "Save Vaporview Session..." and ⌘S always ask where to save (for a file on
  an SSH host: next to it on the host, or on this Mac), and cmux writes only
  the file chosen there; `<dump>.json` is offered only when it holds a
  session. Rename (F2) on a signal opens the rename box instead of setting
  the label to the full path. F2 and ⌘0 work in the viewer, ⌘F also from
  the netlist. Add All in Scope (the netlist menu, the editor) leaves out
  signals already shown (VaporView adds them again), and its warning and
  128 cap count only the rest. An explicit add of one signal (double-click,
  Enter, a drop, the API by id) adds another row, as VaporView does; a pick
  by name or the editor's Add to Waveform selects the shown row, as
  VaporView's add with reveal does. An add made while an Undo, Redo or
  restore looks up its rows waits for that view and counts its rows as the
  shown ones; a reload or open in between drops it.
  Instance-path terminal links never take file names (see
  `WaveformTerminalLink.swift`), and there is no WCP server or remote
  (surfer) viewer.
- `host.js` also reads FSDB files through cmux's FSDB helper (below) and
  delivers every signal's value changes through one function that dispatches
  the message event on the same-origin viewer frame instead of posting it, so
  large signals are not structured-cloned. FSDB value changes arrive as
  packed records and are decoded with one shared string per distinct value.
- `fsdb-helper/` (new): what cmux uploads to an SSH host to read FSDB there.
  `fsdb-helper.js` is adapted from `src/extension_core/fsdb_worker.ts`: the
  same addon calls, served over the ssh stdio channel (newline-delimited JSON
  requests; replies on fd 3, because Verdi's reader prints to stdout) instead
  of Node IPC, with the scope/variable walk done in the helper and signal data
  sent as deflated `[u64 delta time][value chars]` records. `fsdb_reader.cpp`
  is upstream `src/fsdb_reader.cpp`, unmodified; `packed.cpp.inc` adds
  `getValueChangesPacked`, which returns a signal's value changes as one
  packed buffer, and `build.sh` splices it in before `Init()` and compiles
  the addon on the host with `g++` against that host's Verdi (in place of
  `binding.gyp`/node-gyp, without `-static-libstdc++`), installing under a
  lock and never replacing a working install. `fsdb-helper.sh`
  starts it in a private run directory, and exits 87 so cmux rebuilds when
  the Node.js or Verdi it was built for is gone. `getValueChangesPacked`
  also returns the signal's bit size, throws for an unknown signal or no
  open file (where upstream's calls would dereference null), and hands its
  buffer to Node without a copy. `third_party/` holds the node-addon-api 8.6.0 and
  node-api-headers 1.9.0 headers (MIT) the build needs.
- `fsdb-helper-v2/` (new): the windowed viewer's helper (protocol 2 in
  cmux's WINDOWING.md), uploaded and built on the host like `fsdb-helper/`.
  `helper.js` coordinates a pool of `worker.js` processes (four), each with the
  file open and its signals in the addon's compact store, and answers
  `window`, `valueAt`, `edge`, `search`, `searchText`, `count`, `cancel` and
  the v1 `signals`; `expr.js` evaluates derived signals; `text.js` runs
  `searchText` with `formats.js`, the viewer's own value formatters bundled
  from `src/webview/` (`riscv_disasm.ts`, `value_alias.ts`, `value_format.ts`,
  `value_search.ts`; see `fsdb-helper-v2/NOTICE`); `tree.js` keeps the reader's
  arrays as scopes in `children` (each with its elements inline). `addon/fsdb_reader.cpp` is
  upstream `src/fsdb_reader.cpp`, unmodified apart from a two-line license
  header; `build.sh` splices in
  `packed.cpp.inc`, `window.cpp.inc`, `deval.h` and `derive.cpp.inc` and
  compiles it with `g++` against the host's Verdi (and zlib), and
  `cmux-helper-v2.sh` starts it under `nice` in a private run directory,
  refusing an install anyone else can write. `WaveformFSDBHelper` falls back
  to `fsdb-helper/` when this one can't be built or started, and the
  `fsdbLoading` setting (Whole signals) uses `fsdb-helper/` only.
- `cmux-debugger.js` (new, written for cmux): the waveform debugger's page
  side. It picks a clock, steps the marker by its posedges, plays them at a
  set rate, keeps a Locals group of the editor's instance and highlights the
  rows the editor highlights, using only messages the webview already handles.
  Locals leaves out signals shown outside it, so a signal added from Locals'
  scope shows once, and goes back to Locals when that row is removed. A
  Locals row the user deletes stays deleted until the scope's pinned
  signals change; Locals is never in the undo state, so Redo of that delete
  changes nothing.
  `wellen-worker.js` gains `getsignalchanges`, which keeps a signal's data in
  the page (decoding wellen's LZ4 frame, written from the LZ4 format
  description) instead of sending it to the viewer frame, and answers null
  past a change cap; `host.js` exposes a
  variable's changes and VaporView's events to it; `cmux-commands.js` leaves
  the Locals group out of sessions and undo.
- `cmux-sim.js` (new, written for cmux): live simulation, behind the
  `liveSimulation` setting (off by default). It reruns the simulator that
  wrote the open FSDB through `fsdb-helper-v2/sim.js` (cmux pins the run to
  the dump's folder), watches the rows on screen, and hands their changes to
  the viewer through `live.ts` in the patch (`window.__vvLive`: append, gap,
  missing, extend, valueAt, coverage, setLimit), which grows the time range with
  the view following the right edge. Time without a record of a live row (before
  its watch, after an unwatch, changes the helper dropped, history evicted past
  the viewer's limit) is missing coverage: a grey hatch, apart from x, and
  `host.js` value queries answer null there. Run, Stop, Step and Run Until sit in
  the status strip; End Live reloads the dump. `host.js` tells it when a file
  opens or closes, which ends the run.
- `cmux-enum.js` (new, written for cmux): SystemVerilog enum member names.
  cmux reads a signal's enum type from slang-server and hands it to the page,
  which loads it as a value alias table (VaporView's `alias:<table>` format
  from `extra_formats.ts`) and makes it the default format of rows the user
  adds; restored, undone and user-chosen formats are kept, and a dump with
  its own enum type (VaporView's `enumType`) keeps VaporView's. Value Format >
  Enum Names (`cmux-commands.js`) gives a row its table back. `host.js`
  `link.valuesAt` takes `raw` and answers `{bits}` (for cmux to name) for a row
  in its enum's own format or not shown, and a row's text otherwise.
- `cmux-fsm.js` (new, written for cmux): the state machine pane. Show State
  Machine on a vector row (`cmux-commands.js`) asks cmux, which finds the
  register's machine (Verdi's FSM analysis, Yosys's FSM passes, or the dump
  alone; `fsm/cmux-fsm-verdi.sh` is the Verdi side, run on the dump's host
  with the user's own Verdi) and hands the model to the pane. It draws the
  states and transitions as a layered SVG graph, dashes transitions only the
  dump takes, marks the state at the marker and the transition into it,
  moves the marker to a transition's next occurrence (Shift: previous) or a
  state's next entry, and counts entries and transitions over the dump
  (`host.js` `signalChanges`). The pane sits beside the viewer in `index.html`.
- `vscode-theme.css` (new): the `--vscode-*` theme variables VS Code injects
  into webviews, with dark and light values; cmux overrides the background and
  foreground with the panel's colors.

The Swift side (`Sources/Panels/FilePreviewWaveformSession.swift`,
`Sources/Panels/WaveformViewerSchemeHandler.swift`) serves this folder and the
opened file over the `cmux-waveform:` URL scheme, persists the settings,
saves and loads session files, and lets VaporView's keys through to the page
while it has focus (`WaveformViewerShortcuts`);
`Sources/Panels/WaveformViewerStrings.swift` localizes the page's strings;
`Sources/Panels/WaveformTerminalLinks.swift` (adapted from
`src/extension_core/terminal_links.ts`) turns ⌘-clicked times and instance
paths in a terminal into marker moves and added signals; and
`Sources/Panels/WaveformFSDBHelper.swift` installs and runs the FSDB helper on
an SSH workspace's host and relays the page's FSDB requests to it.

## Updating

Rebuild at the new upstream commit with the commands above, copy the files in
the table, re-apply the `viewer.html` changes, check that the message names in
`src/webview/vscode_wrapper.ts` and the exports in
`src/wellen_parser/filehandler.wit` still match `host.js` and
`wellen-worker.js`, regenerate the menus in `cmux-commands.js` from the new
`package.json`, and update the commit here and in `THIRD_PARTY_LICENSES.md`.
